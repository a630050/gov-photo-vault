# 機關內部照片管理系統本機版

這是可持久化資料、登入與實際上傳圖片的本機開發版本。入口為 http://127.0.0.1:8000 ，只綁定 loopback，不是正式內網部署。

## 啟動

在此目錄執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
```

也可以執行 `python manage.py runserver 127.0.0.1:8000 --noreload`。預設埠已占用時使用 `start-local.ps1 -Port 8001`。關閉服務視窗或 Ctrl+C 停止；重新啟動資料仍保留。

首次依賴已下載至 `.vendor`，Leaflet 程式及樣式已複製至 `static`，一般啟動不需連外。重新安裝依賴用 `python -m pip install --target .vendor -r requirements-local.txt`；此本機包配合 Python 3.15 使用 Django 6.1.3，與正式方案 Django 5.2 LTS 的基線不同，正式環境須重新驗證受支援的 Python／Django 組合。

## 測試帳號

所有示範帳號初始密碼：`LocalPhoto!2026`。僅供本機測試，不要使用真實機關密碼，也不要將此開發伺服器公開。

| 帳號 | 角色 |
|---|---|
| admin | 系統管理者；可建科室、帳號、授權、匯出及設定半徑 |
| supervisor | 工務科主管；可審核、封存、復原、處理異常 |
| member | 工務科同仁；可上傳、整理、提出申請 |
| viewer | 工務科僅閱覽；可看與打星，無原圖下載與整理權 |
| other | 環保科同仁；看不到工務科照片，供跨科權限測試 |

`python manage.py seed_demo` 只建立缺少的示範資料，不重設既有密碼。內建七張系統產生測試圖，六張工務科、一張環保科，不是真實現場照片。

## 建議操作順序

1. 使用 member 登入，查看照片圖台、複選科室／資料集、膠囊標籤及日期；科室樹與標籤區可收折並記憶狀態，點照片測縮放、拖曳、右鍵／空白鍵屬性與 Esc。
2. 點「比對附近照片」，下方選另一張，左側調整 100–1000 公尺距離；同一條時間滑桿有起訖雙把手。切換疊合後，直接在照片上左右拖曳分隔線。
3. 在上傳頁選資料集，加入自己的 JPEG／PNG／WebP。到草稿填必填欄位，確認時間、經緯度後正式提交。
4. 勾選照片測批量打星、標籤及撤回本次標籤；不同人加入同標籤後撤回其中一人，另一人的來源仍保留。
5. member 對正式照片提出更正、刪除或搬移申請；登出換 supervisor 在案件頁核准或駁回。核准刪除後到回收區查看及復原。
6. 使用 admin 在管理後台建立科室／視覺化表單／資料集／帳號，改科室角色、停用帳號、封存資料集或設定半徑。選照片匯出 ZIP 原圖與 UTF-8 CSV。

## 視覺化表單與資料集管理

使用 `supervisor` 或 `admin` 登入，進「管理後台 → 表單設計」。選科室及表單名稱，用「＋ 單行文字／多行文字／整數／小數／日期／下拉單選／多選選項／是／否」新增欄位；每欄可命名、勾選必填、上下排序或刪除。選項型欄位用「新增選項」與「移除」管理，選項不可空白或重複。先預覽，再發布表單；編輯既有表單會發布新版本，衝突時拒絕覆寫。

到「資料集管理」選科室，建立資料集並選擇已發布的同科室表單，也能為既有未封存資料集重新指定。更換表單及發布版本只影響新上傳照片，既有照片與草稿保留當時欄位及資料。停用表單不能新指定；封存資料集須重新開放才可換表單。一般同仁不能發布或重新指定表單。

本次瀏覽器實測保留「設施巡查表（操作測試）」與「設施巡查（操作測試）」資料集，可直接用來測試必填下拉欄位。既有「本機測試資料集」仍使用原道路巡查表單。

## 上傳與批次填寫

1. 進入「上傳照片」，先選有上傳權限的科室及未封存資料集，畫面自動顯示指定表單名稱、版本與欄位。
2. 選擇照片並按「上傳並建立草稿」。逐檔接收、產生預覽並顯示成功或失敗，已成功照片不需重傳。
3. 勾選草稿，在「批次填寫共同欄位」勾選要套用的欄位，填值再按套用。只影響勾選照片及欄位；每張原有拍攝時間、GPS 與其他欄位不會被批次覆蓋。不同舊版表單只顯示識別、型別及選項都相容的共同欄位。
4. 點縮圖逐張修改。可查看照片原始擷取時間、時區及 GPS，並在下方修正目前使用值。缺時區以臺灣時間推定並提示；時間或 GPS 缺漏不以目前位置／上傳時間替代。舊版草稿未保存來源時明示缺少原始擷取紀錄。
5. 可先「儲存這張草稿」或「儲存已選草稿」。按「檢查並確認提交」會先儲存，列出可提交張數、必填缺漏、每張表單與拍攝資訊；勾選已檢查才可確認提交。未完整或失敗照片保留草稿，可繼續補填，不影響其他成功照片。

草稿的欄位修改未按儲存前暫留在目前頁面；切換資料集再切回仍保留，但關閉或重新整理前需儲存，瀏覽器會提醒。`test-fixtures/upload-gps-1.jpg` 與 `upload-gps-2.jpg` 是系統產生、帶 EXIF 時間與 GPS 的測試圖；瀏覽器驗證已上傳並提交至「設施巡查（操作測試）」，第一張設施狀況為「待修繕」、第二張為「正常」。

## 人員權限與申請審核

系統管理者登入後，進「管理後台 → 帳號與設定」，選人員、科室及科室角色。主管身分授予所管科室的審核能力；上傳、整理與提出申請、原圖下載、表單管理、批次匯出可分別勾選。可移除單一科室授權，或停用整個帳號；不允許停用最後一名有效系統管理者。權限異動記錄前後狀態，後端每次操作重新驗權，不能只靠介面隱藏控制。表單管理能力不會授予帳號管理能力。

同仁開啟正式照片，修改屬性後按「申請上述資料更正」，會顯示原值與提案差異並要求理由；刪除申請也須填理由，送件時不會直接刪除。到「案件與通知 → 我提出的申請」追蹤，待審時可撤回。

主管在「我的審核待辦」檢閱，填理由後核准或駁回。本人送出的案件由另一位主管或系統管理者審核；照片版本變更時不可直接核准舊案，應駁回重新申請。每案保留原始快照、提案、提出人／時間、處理者／時間、理由及事件時間軸，正式更正另留修改前 Revision，通知已讀不影響案件狀態。刪除核准後移入回收區，其他待審更正搬移申請失效並通知；申請者可見處理結果，但一般照片存取仍被阻擋。

舊版案件若未存完整快照或精確結案時間，介面會明示來源不足並保留原有理由與處理者，不捏造歷史資料。新建案件完整記錄上述欄位。測試範例：member 對 local-sample-6.jpg 提出現場說明更正，supervisor 已核准；可在可查看的案件紀錄查看整個流程。

## 圖台搜尋與同步

照片圖台支援科室／資料集複選、標籤膠囊複選、拍攝日期起訖、我的星號、人工異常狀態（任何紀錄、無紀錄、待確認、確認異常、已排除）、正式／草稿／回收區與檔名查詢。同類選項任一符合，不同種類條件同時符合；科室全選與資料集選取是範圍聯集。科室、標籤與自訂欄位區都可收折。

只勾選一個資料集（不勾整科）後，自動顯示該資料集目前及歷史表單欄位。文字可查包含字串，數值及日期可設範圍，單選／多選可點膠囊複選，是／否可以選擇真假，另可找未填或舊版沒有此欄位的照片。零與否不當成未填；欄位依識別及型別匹配，不把同名不同欄位合併。改選科室或資料集會清除原有自訂條件。

拍攝日期以臺灣時間計算，迄日包含完整當天。沒有時間的照片在未篩日期時仍可查到；篩日期後顯示被排除的無時間張數。所有張數與照片皆先套後端權限。

地圖與清單取用同一次搜尋結果及最新照片資料。預設只顯示地圖範圍，平移縮放同步更新標記、群聚及清單；取消範圍限制後清單也納入無座標照片，這些照片仍不會在地圖上假造位置。點群聚可限定查看該組，按「返回全部搜尋結果」解除；按「縮放至搜尋結果」回到全部匹配照片的位置。改條件保留地圖位置，空清單時可確認是否照片在範圍外。

文字查詢有短暫延遲合併，過期回應不覆蓋新結果；錯誤條件會顯示原因並清空標記與清單。篩選及地圖範圍改變會移除範圍外的勾選，批次打星、標籤及匯出僅處理目前清單內已勾選照片。

## 附近照片比對

開啟有座標的正式照片，按「比對附近照片」。距離滑桿可選 100 公尺至 1 公里，時間用同一條滑軌的兩個端點調整，也可輸入臺灣時間精確起訖。改條件即更新候選，超出範圍的已選照片會取消；「全部時間」恢復附近照片的完整時間範圍。候選沿用科室與標籤條件，可另勾「僅目前資料集」；未勾時可跨有權限的資料集比對。缺座標的照片不列入，缺拍攝時間的附近照片另顯示張數。

點候選照片後可切換左右並排或拖拉疊合。滾輪縮放、拖照片平移，開啟「同步縮放與移動」後兩張使用相同相對比例與位移；拖疊合分隔線只改變露出範圍。分隔線也支援方向鍵、Home／End；「重設檢視」恢復兩張大小、位置及分隔線。兩張各有拍攝時間、座標、科室／資料集、表單版本與欄位、標籤及人工異常，可收折屬性增加照片空間。不同拍攝角度仍須人工對齊，目前未做自動影像配準。

附近查詢由後端套用權限與球面距離，快速操作時只採用最新回應；本機版仍在授權範圍內掃描，正式大規模環境需空間索引。

## 手動近似分析

到「近似分析」選擇單一資料集，設定拍攝時間差門檻（小時，預設 24），再按「手動執行近似分析」。預設分析該資料集全部正式照片，也可只分析圖台已勾選、且屬於該資料集的照片。本機單次支援 2–300 張，不會靜默截斷；不跨資料集，也不在上傳後自動分析。相同名單與參數的未完成工作會繼續使用原紀錄。

每次保存執行者、名單與版本、時間門檻、演算法與指紋門檻。離線 `dhash64-ahash64-v1` 對原圖套用 EXIF 方向後，計算 64 位元 dHash 與 aHash；兩種漢明距離皆不超過 6 才列為近似配對。門檻為本機固定設定，不是經業務資料校準的模型分數。相同或重新壓縮的照片可用此方法檢閱；相同場景仍可能誤報，裁切、旋轉及明顯視角變化可能漏報，尚未完成正式 precision／recall 品質驗收。

結果保留所有影像近似配對，分開標示「時間差嚴格超過門檻」、「未超過門檻」及「時間需確認」。24 小時整不算超過 24 小時；缺拍攝時間或尚未確認時間，不以建立／上傳時間替代。每對可直接開啟並排、同步縮放移動及拖拉疊合，不需要 GPS。可標記已檢閱無須處理，或填說明後為兩張建立待確認人工異常，再由主管於照片屬性確認、排除或重開；演算法不自動判定造假。配對檢閱保留操作者、時間與說明，同時編輯會要求重新載入，重新分析不直接沿用舊結論。

本機以每批 10 張的請求處理，原圖每次分析只解碼一次，再逐對比較指紋。可取消，離開頁面後在目前批次完成處暫停，返回時手動繼續；不是獨立背景 worker。讀取失敗的張數及 ID 會明示，結果僅涵蓋成功讀取的照片。結果每頁 50 對；照片更正、搬移或回收會標示舊結果已變動，開圖與標註仍重新驗權。需要另授「資料集近似分析」能力（預設同科同仁／主管具備），不以整理或跨科閱覽權代替。

## 離線中文照片內容搜尋

到「內容搜尋」輸入中文關鍵字或短句，例如「交通錐」、「道路積水」。搜尋使用原圖的影像向量與文字向量，不依檔名、標籤或表單文字排序。可限定一個或多個可閱覽資料集；未勾選時包含全部可閱覽資料集。只有正式照片列入，草稿與回收照片不列入。後端在排名前與回傳前重新檢查目前權限，唯讀人員可搜尋，但不能新增共享標籤。

本機已安裝 Chinese-CLIP RN50（官方權重版本 `717ba215769231e53b9b7c6b9d329b9cc5944418`），使用 1024 維單位向量及精確餘弦排序，繁體查詢先在本機轉簡體再分詞。預設最低相近度 0.20，可自行調整；分數不是準確率，門檻仍需用機關照片校準。每次最多回傳 500 張，超過時明示截斷，應縮小資料集或提高門檻。找不到結果時也顯示授權範圍內已索引、待索引及失敗數，不把索引不足當成全庫沒有照片。

勾選照片或按「選取全部搜尋結果」，輸入標籤後，畫面會預覽張數與標籤，按確認才新增；全部選取只包含當次已回傳、可整理且未封存的照片。送出時整批重驗權限，任一照片失權或封存則本批次不寫入。重複標籤不重複顯示，仍保留獨立批次來源；可撤回本批次來源，其他批次新增或保留的標籤不會被撤掉。此流程也修正同一照片一次撤回多個標籤時的舊資料覆寫問題。

`start-local.ps1` 在模型檔案存在時會啟動隱藏的內容索引程序，處理既有及新提交的正式照片；停止主程式時，索引程序會在目前批次結束後停止。單獨執行 Django 時，請另開一個終端執行：

```powershell
python manage.py semantic_index --watch
```

只建一次索引用 `python manage.py semantic_index`；修復失敗原圖後，用 `python manage.py semantic_index --retry` 重試。索引記錄固定模型版本與原圖 SHA，舊模型向量不混排，原圖雜湊變動會重新索引。模型不可用時顯示錯誤，一般照片圖台與人工整理仍可操作。這是 SQLite 本機精確掃描版，尚未驗證大型資料量與正式搜尋品質。

首次在允許連外的準備環境執行 `powershell -ExecutionPolicy Bypass -File .\setup-semantic.ps1`，需先有 `uv`。腳本把 Python 3.12.13、CPU PyTorch 與推論依賴放入專案 `.runtime`，不更動系統 Python；下載固定官方權重並驗證 SHA-256。之後的索引及查詢完全離線，模型程序禁止 socket 連線，無執行期下載。權重及中文詞庫在程序啟動時再次核對雜湊；套件版本見 `requirements-semantic.txt`，CPU torch／torchvision 版本固定於準備腳本。

模型來源及授權：Chinese-CLIP 程式採 [MIT](https://github.com/OFA-Sys/Chinese-CLIP/blob/master/MIT-LICENSE.txt)，RN50 [官方模型卡](https://huggingface.co/OFA-Sys/chinese-clip-rn50/blob/717ba215769231e53b9b7c6b9d329b9cc5944418/README.md) 標示 Apache-2.0；詞庫／BERT 檔案保留其上游授權。`.runtime` 與 `models` 不進 Git，也不包含於既有照片備份；移機時需另行準備相同版本模型、授權及環境，SQLite 備份則已包含內容索引。模型載入診斷在 `.runtime/semantic-worker.log`，自動索引輸出在 `.runtime/indexer-output.log`／`indexer-error.log`。

## 科室名冊與離線人臉搜尋

「人物名冊」依科室分開，人物使用 UUID 與科室內唯一編號；同名可建多筆，不跨科室自動合併。姓名、備註、啟用狀態支援版本檢查。每人可有 20 張啟用參考照片，每批上傳 1–5 張、每張最多 10 MB；上傳後先移除 EXIF、校正方向、轉成 JPEG，再檢查是否只有一張清晰人臉。無臉、多臉、過小或模糊的參考照片會逐張說明失敗原因。可停用／重新啟用參考照片，不提供永久刪除捷徑。

先在「管理後台 → 帳號與設定」授予對應科室的「人物姓名與關聯閱覽」、「離線人臉搜尋」、「科室名冊與人物關聯維護」。三者預設均關閉，系統管理者亦不例外。閱覽人物是其他人物操作的必要條件；只有搜尋者可看候選但不能確認，維護者可管理名冊，若要操作搜尋候選的人工確認，還需要搜尋權限。只有姓名閱覽權時不顯示參考照片。照片原有閱覽權仍獨立套用。

選擇人物與本科室資料集後，手動按「建立／繼續本範圍人臉索引」，每批處理 5 張有權閱覽的正式照片；可停止後續批次、重試失敗或離開後再繼續。草稿、回收照片與其他科室不列入；索引過程不建立人物關聯。每張照片保存各張可用人臉的正規化框、128 維向量、品質、原圖 SHA 與模型版本。索引失敗及涵蓋不足會明示，無可用人臉不強制產生候選。

按「以此人物的啟用參考照片搜尋」，以各啟用參考向量中的最高餘弦分數排名，列出人臉框、照片與分數，最多 500 張候選人臉；超過會提示縮小範圍。一圖多臉分別檢閱。此版採示範門檻 0.363，不是身分正確率，正式啟用前需用機關資料驗證誤匹配／漏匹配及調整門檻。

有名冊維護與搜尋權限者，核對參考照片及候選原圖後填寫理由，再按確認才建立人物關聯。候選簽章有效一小時；送出時重新檢查權限、人物與參考版本、照片版本／SHA、正式狀態與封存狀態。失效候選須重搜。同一人臉不會同時確認為兩人，應先撤銷錯誤關聯。確認、撤銷及再次確認均保留操作者、理由與時間；可從照片屬性看到已人工確認人物，但沒有姓名閱覽權時不顯示。回收、移動至別科室、撤權或影像變動會立即影響可見候選與關聯。人物停用後不再搜尋或顯示目前人物關聯，歷史保留。

本機已準備 [YuNet](https://github.com/opencv/opencv_zoo/tree/48b10fa505aeb51fbd127fc60a5c660040e823b7/models/face_detection_yunet)（MIT）與 [SFace](https://github.com/opencv/opencv_zoo/tree/48b10fa505aeb51fbd127fc60a5c660040e823b7/models/face_recognition_sface)（Apache-2.0），使用固定 OpenCV 4.12 CPU 環境。換機時在允許連外的準備環境執行 `setup-face.ps1`，之後執行期不下載、模型程序禁止網路連線。權重在安裝及載入時核對 SHA-256；中文 Windows 路徑透過模型記憶體緩衝載入。依賴見 `requirements-face.txt`，授權在 `models/face`，診斷在 `.runtime/face-worker.log`。參考照片納入 `storage/people` 受控儲存及既有照片備份，向量／關聯在 SQLite；模型與隔離環境需另外備妥。

人物相關稽核保存在資料庫，關聯歷史由人物專用入口依權限查看，不透過一般後台稽核清單透露人物識別及照片關聯。完整人物資料保存／刪除政策、大規模索引與跨族群品質驗收仍待正式階段確認。

功能測試採獨立資料庫及 [scikit-image 的 NASA 公有領域測試照片](https://scikit-image.org/docs/stable/api/skimage.data.html#skimage.data.astronaut)，未把測試人物或專用權限寫入目前本機資料。測試圖的重新壓縮比對僅是管線驗證，不代表正式辨識準確率。

## 外部上傳接收閘道（本機流程驗證）

下一階段已提供獨立接收閘道與內網拉取程序。本機核心仍在 `127.0.0.1:8000`，閘道在 `127.0.0.1:8002`；目前皆只綁定回環介面。啟動核心後，另執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-external-local.ps1
```

腳本先執行 `prepare_external`、初始化獨立閘道資料庫，再啟動閘道與隱藏的內網拉取程序。停止閘道腳本會通知拉取程序在目前工作結束後停止，不會關閉核心系統。也可分開執行 `python manage-gateway.py runserver 127.0.0.1:8002 --noreload` 與 `python manage.py external_bridge --watch`；只同步一次用 `python manage.py external_bridge`。

在核心的「外部上傳」選擇有上傳權限、未封存的資料集，設定 1–24 小時與 1–50 張額度。通行碼只顯示一次、只存 SHA-256，綁定本人、資料集及不可變表單快照。等紀錄顯示「閘道已同步」後，在閘道使用通行碼登入；首次登入即兌換，之後保留該瀏覽器工作階段查看本人進度。登出或遺失工作階段後，應在內網另建新碼。通行碼可由本人或系統管理者撤銷。

閘道只有登入、本人目的地、本人暫存預覽、上傳確認及進度，不提供核心的圖台、歷史照片、人物、管理後台或原圖下載路由。其資料庫、檔案區、Session／CSRF cookie 與核心分開，不持有核心帳號密碼或 SMB 憑證。接收與控制路由分開驗證；內網用獨立密鑰呼叫控制路由，瀏覽器登入不因此取得該權限。

正式放入 DMZ 的程式應只包含 `external_gateway`、`transfer_common`、`gateway_settings.py`、`manage-gateway.py` 與其必要依賴及閘道設定，不應整份複製或掛載核心專案資料。共用 EXIF 與表單驗證放在不含核心模型的 `transfer_common`；閘道啟動入口也會拒絕誤載內網核心設定或路由。

外部每批最多 5 張、每張最多 10 MB，接受 4000 萬像素以內 JPEG／PNG／WebP。選檔後先暫存，顯示自動擷取的時間、座標及指定表單；可勾選照片套用共同欄位、逐張修改，再明確確認提交。進度分清楚「暫存待確認」、「等待內網拉取」、「已匯入內網草稿」、「相同檔案未重複匯入」與「拒絕匯入」。閘道接收成功不代表已完成內網正式提交。

內網程序主動向閘道同步授權、拉取待辦與檔案，再以內網資料重驗：帳號啟用、目前上傳權、授權期限／撤銷、資料集封存、表單識別／版本／快照及張數／容量。原圖會驗證大小與 SHA-256、重新解碼、重新擷取 EXIF，表單值重新驗證，不信任閘道提供的擁有人、目的路徑或拍攝資料。成功只建立上傳者本人的內網草稿，回內網檢查後才能正式提交。表單已更新、失權、到期、額度不符或檔案驗證失敗時明示拒絕，不變成正式照片。

收件 UUID、照片 SHA 與兩分鐘處理租約用於恢復及冪等處理；重試拉取、回報遺失或同一資料集已有相同檔案，不重複新增照片。暫時網路／儲存失敗保留待辦重試，程序中斷後可在租約到期重新接手。授權在檔案取得前與寫入交易內再驗證；閘道撤權同步有延遲時，內網仍依即時授權拒絕匯入。

設定在忽略版本控制的 `.runtime/external-config.json`，包含閘道 URL、獨立橋接密鑰與閘道 Session 密鑰，禁止放入前端或 Git。連線網址只由部署設定提供，不接受上傳者指定；非回環 HTTP 會拒絕，HTTPS 使用預設憑證驗證，控制請求不跟隨重新導向。閘道啟用 HTTPS 設定時強制 HTTPS 與 Secure cookie；若使用受信任反向代理，需由部署者設定並清理轉送標頭。

閘道資料位於 `.external-gateway/gateway.sqlite3` 與 `.external-gateway/files`，不包含於原有核心照片備份；其中可能有唯一一份尚待拉取的照片，必須另做備份及暫存監控。橋接記錄在 `.runtime/external-bridge-output.log`／`external-bridge-error.log`。一般啟動不需外網依賴。

此版本驗證 E01–E03 的主要本機流程，**尚未部署到外網，也未完成 E01–E04 正式驗收**。正式環境仍需實體 DMZ／內網分離、只允許內網主動連出的防火牆規則、反向代理與 HTTPS 憑證、機關 SSO／MFA 及通行碼政策、限流與惡意檔案檢查、配額與暫存保存／清理政策、獨立備份復原演練，以及支援的正式資料庫與服務管理。不得直接把本機 Django 開發伺服器公開。

測試命令：核心 `python manage.py test`；獨立閘道 `python manage-gateway.py test external_gateway.gateway_checks`。端到端介面驗證採隔離測試資料庫，不會把測試通行碼或照片匯入目前核心資料。

* **後端搜尋分頁與統計一致性**：`POST /api/search` 改為後端分頁（預設每頁 100 張、上限 200 張），固定以 `(captured DESC NULLS LAST, -id)` 排序；`total`、`located`、`missing_location`、`region_stats` 與 `burst_matched_counts` 皆代表完整授權搜尋結果。
* **後端地理群聚**：`POST /api/map_clusters` 依目前視窗 `bounds`、`zoom`、搜尋條件與權限於後端計算 Web Mercator 格網聚合（`mercator_bin`）；點擊群聚時以相同群聚條件向後端分頁讀取，確保群聚數字與清單完全一致。
* **圖牆虛擬捲動與跨頁全選**：前端圖牆／清單僅渲染可視區域與緩衝卡片，延遲載入縮圖並支援載入中／失敗重試狀態，縮放縮圖大小後自動校正捲動錨點。支援「選取全部符合條件的結果」（HMAC 簽章 `selection_token` ＋ `excluded_photos`），於執行批量打星、批量標籤或匯出前重新驗證即時權限、照片狀態與上限。
* **統一背景工作中心與獨立 worker**：新增 `BackgroundJob` 資料表（遷移 `0014`）、`core/jobs.py`、`core/views_jobs.py`、`static/jobs.js` 與 `python manage.py job_worker`（支援 `--watch`／`--once`／`ops.py worker job_worker`），納管**大量照片匯出**（最高 5,000 張串流 ZIP）、**手動單資料集近似分析**（保留既有 `SimilarityRun`/`SimilarityPair` 與檢閱歷史）、**行政區批次重算**（含座標樂觀防護避免舊結果覆蓋新座標）與**離線內容／OCR 索引維護**；具備租約逾時接手、批次邊界取消、重試冪等、並行上限（`MAX_CONCURRENT_JOBS=2`，重型模型／分析互斥）及執行與下載即時驗權。

### 本機實測基準（>= 10,000 張照片）
